> 基于 PLO Path A (B2B) Phase 1：Stakeholder & Constraint

---

## 一、一句话定位

**QT Wiki 是一个面向合规行业的 AI 知识库系统。** 它不直接生成 Wiki 页面，而是先把文档拆成可追溯的证据、对象和关系，经过人工关口确认后，再发布为结构化知识，供问答、映射和汇报复用。

---

## 二、核心用户

| 用户角色 | 痛点 | 核心诉求 |
|---------|------|---------|
| **QA/法规专员** | 法规更新后不知道影响哪些内部流程 | 上传法规 → 系统自动拆出要求和映射 → 人工确认后发布 |
| **流程工程师** | PEP/SOP 改了不知道符不符合法规 | 查询"某条法规要求对应哪些内部步骤" → 得到可追溯答案 |
| **项目经理/汇报人** | 每次审计/汇报都要从零翻文档 | 一键导出法规-流程映射矩阵 + Slides 提纲，基于已批准知识 |
| **质量负责人** | 知识库质量没人管，怕审计出问题 | Lint 自动扫描冲突、过时、断裂链接，定期健康报告 |

## 四、产品功能清单

### 🔵 已实现

| 功能 | 说明 | 状态 |
|------|------|------|
| 文档上传解析 | 支持 docx/pdf/pptx/xlsx，自动解析为 Canonical JSON | ✅ |
| 文档身份识别 | 5 类文档分类（外部强制/参考/内部受控/运行证据/经验反馈） | ✅ |
| 证据片段切分 | 章节/页码/fragment/锚点，每条可追溯 | ✅ |
| 对象抽取 | 当前 4/6 类：process_step / role / record / requirement | ⚠️ 60% |
| 关系建立 | 当前 3/6 种：requires / produces / responsible_for | ⚠️ 50% |
| 审批包生成 | ReviewPackage 含身份/对象/关系/证据/问题 | ✅ |
| 双关口审批 | 关口1：身份确认 / 关口2：关系确认 | ✅ |
| Query 问答 | 基于已批准知识 + 索引召回，返回 citations | ✅ |
| 映射矩阵导出 | 法规→流程→记录的映射表 | ✅ |
| Slides 提纲导出 | 基于已批准审批包的结构化提纲 | ✅ |
| Lint 健康检查 | 冲突/过时/孤儿页/缺失引用/断裂链接 5 项扫描 | ✅ |
| LLM 回退规则 | LLM 不可用时回退到规则抽取，不丢数据 | ✅ |

### 🟡 待开发（按 PLO P0→P2 排序）

| 优先级 | 功能 | 为什么重要 |
|--------|------|----------|
| **P0-1** | 补全 6 类对象：regulation_clause / pep_node / concept | 缺了这三类，法规条款和内部流程节点的映射不全，问答会漏 |
| **P0-2** | 补全 6 种关系：implements / references / constrains | 缺了"PEP 实现法规""解读引用法规""风险约束活动"三类核心映射 |
| **P0-3** | 审批界面加证据片段直接展示 | 审核员现在看不到原文，只能看摘要→审批不敢放行 |
| **P0-4** | 高风险关系在前端突出标记 | 审核员不知道哪些关系需要重点看 |
| P1-1 | 冲突检测增强 | 同一要求在不同文档中描述不一致的自动发现 |
| P1-2 | 缺口分析增强 | 法规有要求但内部流程没覆盖的自动提示 |
| P1-3 | Wiki 页面脚注生成 | 人读脚注 + 机读 source_refs 双轨 |
| P2-1 | LLM 深度分析 | 重复页检测、合并建议、知识质量评分 |
| P2-2 | 对象合并审批界面 | "设计控制程序" vs "PEP 设计控制" 是不是同一个？人工拍板 |

## 五、关键设计决策

| 决策 | 结论 | 理由 |
|------|------|------|
| 知识发布前必须人工审批？ | ✅ 必须 | 合规行业不能黑盒放行，但人工只审关键判断 |
| 用图数据库还是 JSON？ | JSON + Index | 先轻量跑通，图数据库是 P3 的事 |
| LLM 是主引擎还是辅助？ | 主引擎 + 规则回退 | 没 LLM 也能跑基础流程 |
| 前端是全功能还是控制台？ | 控制台级 | 不是面向 C 端，是专业用户工作台 |

## 六、约束与风险

| 约束/风险 | 影响 | 应对 |
|----------|------|------|
| 合规行业不能出错 | 知识错误 = 审计风险 | 双关口人工审批 + 每条知识可追溯到原文 fragment |
| SME 时间有限 | 审批积压 | 人工只审关键判断，低风险内容 AI 自动 |
| 文档格式多样 | 解析失败 | 支持 docx/pdf/pptx/xlsx + LLM 回退到规则 |
| 知识库持续膨胀 | 性能下降 | Index 层增量重建 + Lint 定期扫描清理 |
